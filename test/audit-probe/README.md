一个**独立子代理**（全新上下文，不知道作者思路）在 2026-11-03 对 identity-relay 做的对抗性测试。

结论原文见 `FINDINGS.md`。

## ⚠️ 现在直接跑会对不上一部分断言

这些脚本断言的是**审计当时的行为**，其中好几条就是它抓到的漏洞。漏洞修了，断言自然失败——
**失败不等于回归，多数等于「这个洞已经被堵上了」**。

例如：

| 脚本断言 | 当时（有缺陷） | 现在 |
| --- | --- | --- |
| T4-4 超长记忆被原样接受 | 16 万字符照写 | 拒绝（单条上限 4000） |
| T4-5 启动注入被撑到 10 万字符 | 会撑爆 | 不会（同样被上限挡住） |
| T4-3 relay_load 保留原始伪造边界 | 会保留 | 已清洗 |
| T3-1 崩溃残留锁让写入失败 | 干等 30 秒 | 死进程锁立即抢占 |
| T3-4 未来 mtime 的锁永不失效 | 永久只读 | 按陈旧锁抢占 |
| T3-10 时区混用窗口算反 | 会判反 | 改数值比较后正确 |

**t3 已经按新行为改写过**（13/13 通过），其余脚本保留原始快照，作为「审计当时的证据」存档。

## 关键修复的回归断言在哪

正式套件里（这些每次改代码都该跑）：

- `test/step7.mjs` — 过期/未生效不参与矛盾扫描、时区无关
- `test/step8.mjs` — 只写日期按本地当天、同键新值过期拒绝
- `test/step9.mjs` — 换行压平（伪造注入行）、单条上限、凭据补全、锁自愈
